# Technical design

Cosmic Gemini is a Manifest V3 Chrome extension with feature-isolated products: Native Scroll, No Autoplay, Mailto Capture, Website Knowledge Control, Clipboard Protect, Ad Marshal, Any Copy, Page Display, XHS Image Dark Mode, Image Download, Video Download, and Satellites. Its authority chain is `central → province → product → feature`. Central decides jurisdiction and routes work, provinces coordinate their assigned products, products execute independently, and features or nested subfeatures implement the technical operations. Any Copy and Any Copy Enhanced own separate activation, runtime, bridge, and activity-state paths even though they share one settings page.

## Extension layout

The `extension` root contains only `manifest.json`. Chrome entry points and product surfaces are grouped by responsibility: `background/central.js` is the service worker and routing authority, `background/provinces` contains provincial coordination, `background/products` contains independent product execution, and `background/features` contains reusable technical operations. `popup` contains the compact control window, `shared` contains localization and common UI modules, and `workspaces/image-download` contains the Image Download workspace. Page runtimes, domain logic, settings pages, offscreen processing, icons, and bundled third-party libraries remain isolated in `content`, `core`, `settings`, `offscreen`, `icons`, and `vendor`.

## Authority hierarchy

Central records the jurisdiction map and accepts browser events and typed messages. It does not contain product rules, storage mutations, page injection, scanners, scheduling, network fetches, workspace operations, media assembly, or download execution.

Standing Province governs Native Scroll, No Autoplay, Mailto Capture, Clipboard Protect, Access Control, Website Knowledge Control, Ad Marshal, Website Fixer, and Serch Result Language Designate for Google Search (`lang-google`). Operations Province governs Any Copy, Any Copy Enhanced, Page Display, XHS Image Dark Mode, Satellites, extension administration, and otherwise unassigned products. Customs Province governs Image Download, Video Download and Document Preview. Each province exposes the same stable interface while owning its shared policy, event coordination, dispatch, and reset ordering.

Products retain separate state and execution paths. A product may use province-coordinated infrastructure, but it cannot import or control a sibling product. Features such as bridges, runtimes, scanners, adapters, and offscreen processors may contain further subfeatures as required without changing the authority chain. Shared browser and storage primitives live in `background/platform.js`; they provide infrastructure without deciding product policy.

## Page startup

`content/central-page.js` is the only declarative content script. This small isolated entry loads at `document_start`, asks `background/central.js` for a per-frame decision, and contains no product behavior. Central routes the request to the assigned province and product. The product's page-runtime feature injects its isolated bridge and main-world runtime only when that product is active in the current page context. Inactive products are not injected. Native Scroll, No Autoplay, Page Display, and XHS Image Dark Mode remain top-frame products. Mailto Capture, Clipboard Protect, and Any Copy may be injected in matching frames, while Any Copy Enhanced remains limited to its active top tab.

Each injected feature bridge retrieves only its current page state through the authority chain and passes it to its main-world runtime through token-bound events. Stored rule collections and extension APIs are not exposed to page code. Every injected product has separate bridges, runtimes, lifecycle messages, and cleanup paths. When a new decision deactivates one product, that product restores its page changes, removes its listeners and observers, and disposes without starting or stopping another product.

Settings pages contain their complete first-frame structure. A synchronous locale preloader applies the cached Chrome UI locale and cached control values before the page becomes visible. Asynchronous storage then confirms that selection without rebuilding the initial view. The All Settings page also renders its reset control in the first frame.

## Native Scroll

Standard protection prevents matching page-level wheel and touch events from reaching website handlers without cancelling the browser's native default action. It preserves pinch zoom, horizontal gestures, interactive controls, maps, editors, media controls, and ordinary nested scroll areas.

Enhanced protection also handles scripted nested movement and narrowly detected full-page transformed wrappers. Inline style changes are recorded and restored when protection becomes inactive. Listener records use weak references, and DOM observation is limited to structural roots.

Native Scroll restores its page API wrappers, event hooks, observers, and recorded style changes whenever it becomes inactive, then disposes its runtime and bridge.

## No Autoplay

Standard protection blocks `HTMLMediaElement.play()` and captured playback events unless playback follows direct user activation. A short trusted-input window also recognizes custom page controls that call `play()` after their own pointer or keyboard handler. Audio elements and Web Audio may run when the all-sites audio setting is enabled or the hostname matches a saved audio autoplay rule. Audio autoplay permission does not allow autoplaying video.

When No Autoplay is enabled, audio autoplay is denied silently by default. An Always inactive website rule deactivates all media interception and permits video, audio, and Web Audio autoplay. Enhanced protection removes video and audio elements, including matching nodes inserted later. Its subtree observer exists only while Enhanced mode is active.

No Autoplay restores media playback and Web Audio methods and removes its event hooks whenever it becomes inactive, then disposes its runtime and bridge.

No Autoplay operates only on media elements and audio contexts inside the current webpage. The extension declares no `commands` or `nativeMessaging` permission and does not use Media Session action handlers, operating-system media keys, AppleScript, or system audio APIs. Releasing blocked webpage media can call that page element's original `play()` or audio context `resume()` method, but it cannot issue a play or pause command to a separate desktop music application.

## Mailto Capture

Mailto Capture is a Standing Province product displayed as the first item in Satellites settings. It is disabled by default in ordinary and incognito windows, and has no popup control or activity icon. Its independent product module owns the bridge and runtime lifecycle after Central authorizes it through Standing Province.

The runtime uses capture-phase delegated activation handling in every eligible HTTP or HTTPS frame, so dynamically created links require no DOM scan or observer. A trusted left or middle activation of a `mailto:`, `tel:`, or `sms:` anchor is cancelled before the browser hands it to the operating system. The mail parser preserves path and query recipients, repeated To, CC, and BCC fields, subject, body, repeated extension fields, encoded line breaks, and literal plus signs. The telephone parser preserves the complete decoded dialing target, including URI parameters such as an extension. The text-message parser preserves one or more recipients, the message body, repeated extension fields, encoded line breaks, and literal plus signs.

The page popover is created only after an intercepted activation and uses a closed Shadow DOM. Recipient values and telephone numbers are plain selectable text rather than links. A mailto value containing only one address offers Copy address. If it contains any additional recipient or field, the popover instead offers Copy message for the complete structured content. A tel value offers Copy number. An sms value containing only recipients offers Copy number; one containing a body or extension field offers Copy text message for the complete structured content. NANP telephone numbers use conventional `+1 (NPA) NXX-XXXX` or `(NPA) NXX-XXXX` display formatting in the popover, including a readable `ext.` suffix for the standard telephone-URI extension parameter, while copied content retains the original complete dialing target. Recognized North American numbering-plan locations appear in English on a subdued second line directly below the corresponding telephone number; an unrecognized number receives no location line or error text. Long US city or metropolitan-area prefixes wrap naturally while the final `state, USA` remains one inline unit. The complete `North American Numbering Plan` suffix uses the same rule. Either suffix stays on the current line whenever it fits instead of being forced onto a separate line. The bundled offline NANP reference is compiled from current NANPA and CNA allocation data. It uses a three-digit area result whenever that area code reliably identifies one city or metropolitan area, retains NPA-NXX detail only for area codes spanning multiple localities, and falls back to the broader state, province, territory, country, or service classification when an exact assigned prefix is unavailable.

International numbers beginning with `+` use a separate 84 KB precompiled reference generated from pinned libphonenumber metadata. It contains only country-calling-code assignments, shared-code disambiguation patterns, international display grouping rules, English and Simplified Chinese China fixed-line area locations, compact Simplified Chinese country and region short names aligned to GB/T 2659.1 country codes, and Mexico's eight one-digit numbering zones. General validation APIs, examples, carrier data, timezone data, and mobile geocoding are removed before packaging. The runtime identifies the country or territory, applies the corresponding international display grouping, localizes non-NANP location output to the interface language, and caches at most 64 results per locale. NANP locations remain English in either interface language. For `+86`, fixed lines can resolve their two- or three-digit area code while mobile numbers intentionally stop at the country level; Chinese output removes administrative generic suffixes. English layout keeps the province-level region with `China`, while Chinese layout keeps `中国` with the province-level region. For `+52`, the first national digit selects the official directional name for Zone 2 through Zone 9 without adding a city-level prefix table. All location output describes numbering-plan allocation rather than a device's live location. Clicking outside, pressing Escape, disabling the product, replacing the page document, or disposing the runtime removes the popover and all associated state. The product never navigates to the intercepted target and does not retain email addresses, telephone numbers, or message fields.

## Clipboard Protect

Clipboard Protect is an independent Standing Province product directly below Website Knowledge Control in Satellites. It defaults off in ordinary and incognito contexts, has no popup icon, and is authorized through Central for eligible HTTP(S) frames. Its saved switch remains independent from Any Copy, NSNA rules, and current page activity.

During a trusted copy event with selected non-editable text, the runtime captures that selection and writes its original plain text plus an inert, sanitized HTML fragment where available. A narrow clipboard-event getter hook captures the selection before an earlier website handler writes added content; a guarded propagation hook keeps the final copy handler reachable. It does not block arbitrary events or replace clipboard APIs globally. Both hooks and the copy listener are removed on disable, and retained wrappers become inert. No page scan, DOM observer, polling, clipboard-read permission, clipboard history, or network request is involved.

Design-mode documents, inputs, textareas, contenteditable regions, ARIA textbox/grid/treegrid controls, and common code editors are excluded. The decision checks the event path, focus (including open shadow focus), selection endpoints, and shadow hosts. Those editors retain their own plain text, rich HTML, and custom clipboard formats. Copy buttons without a text selection, cut/paste operations, and synthetic events also keep their normal handling. A protected ordinary selection takes precedence over a site's custom copy formatting, while basic selected markup and links remain available.

The product protects selected-content copy events, not every possible write to the system clipboard: unrelated or later asynchronous Clipboard API writes are outside its scope. It does not read existing clipboard contents. It neither enables nor changes Any Copy; that product retains its own saved behavior. Central resolves Any Copy's effective per-page state, including coordinated activation and a current-tab pause, and directs Clipboard Protect to yield while Any Copy is active. During transitions, Central stops the outgoing copy guard before starting the incoming one, so the two main-world copy guards do not remain active together.

## Page Display

Page Display is a default-off Operations Province product with its own settings page and a dedicated master authorization. Its settings navigation entry uses a brightness-sun icon immediately left of Satellites. It owns two independently configured subfeatures: Reduce White Point and Greyscale. Central authorizes one top-frame runtime for ordinary HTTP or HTTPS pages only while the master and at least one subfeature are enabled. Reduce White Point stores an adjustable reduction from 10 to 80 percent, with a default of 25 percent; Greyscale stores only its enabled state.

The runtime creates one fixed, pointer-transparent visual layer in a closed Shadow DOM. Reduce White Point normally uses a black compositing surface with adjustable opacity. When a page-wide dark-mode filter would invert that surface, it uses the corresponding white pre-inversion surface so the final rendered result still retains or reduces luminance. Greyscale filters the rendered surface through the same host. Both effects cover ordinary page content, images, Canvas, animations, embedded frames, and video without changing layout, wrapping, scroll geometry, focus, selection, or pointer and keyboard input. Fullscreen changes remount the same layer in the active fullscreen root.

Turning off one subfeature removes its visual contribution. Turning off the master or both subfeatures removes the layer and its fullscreen listener before the bridge and runtime are disposed, restoring the page to its prior appearance. The master preserves both child selections while making every child control unavailable. Enabling either popup child can enable the master and that child in one saved action. While the master is off or both child features are disabled, no Page Display code is injected. Reduce White Point observes only root, body, and head appearance changes while active so it can follow page-wide filter changes. It does not observe content nodes. The product uses no page API wrappers, polling timer, network request, or content inspection.

## XHS Image Dark Mode

XHS Image Dark Mode is a default-off Operations Province product presented after Clipboard Protect in Satellites settings. Its page product is authorized only for the exact top-frame host `www.xiaohongshu.com`. The popup uses a contextual-product registry to add its open-book-and-bulb control below the fixed product rows only on that host, leaving the row position open for future contextual products.

When enabled, the product checks the page's actual rendered surfaces first. It samples visible viewport positions, composites transparent background layers, and recognizes page-wide inversion filters before consulting Dark Reader markers or site theme attributes. Dark Reader's dynamic, filter, and static engines are recognized through their current root attributes, active styles, and instance marker. Theme styles, metadata, visibility changes, and several short checks during initial page setup cover extension injection order. A dark color-scheme declaration alone is not enough to activate processing. The product does not start image work until page-wide dark mode is detected, unless the user enables the explicit override. That override authorizes processing immediately and makes the contextual control active without waiting for a page-status round trip. The waiting state uses a blue open-book-and-hollow-bulb icon without a background. Active image processing fills the bulb and adds a blue background, while the disabled state remains neutral and hollow.

Image classification preserves the source aspect ratio and downsamples to no more than 1,024 pixels. Quantized colors identify a dominant flat reading surface, while a separately sampled perimeter can identify a stable structural frame without depending on its hue, saturation, or brightness. Sliding horizontal samples also recognize layouts containing contiguous light and dark panels without treating isolated text rows as structural regions. The classifier then measures combined surface share, contrasting foreground share, and the largest connected foreground region. A light or split-panel text layout, including a framed note card, receives the whole-image inversion transform. A uniform low-chroma mid-gray card with bounded light text instead receives a high-contrast transform that maps its background toward black without inverting the light text or small color accents. Photographs, mixed photo-and-text images, blank areas, avatars, and uncertain images remain untransformed. The runtime creates no regional mask, transformed clone, or face-detection task.

The feed is analyzed ahead of the viewport through an intersection margin. Visible and expanded-view work is admitted on animation frames, while work farther ahead returns to browser-idle scheduling between images so a growing feed cannot monopolize the main thread. When a post viewer opens, the active slide is queued first, adjacent slides next, and the remaining slides afterward. Every carousel image is classified independently. Avatars and the detail-view follow button receive only a modest brightness reduction while processing is active.

Completed ordinary photographs immediately leave the runtime's record set and intersection observer. Completed transformed cards remain only so their visual state can be removed later. Resize observation and scroll-position work are restricted to the small set of expanded-view images that own controls, rather than every feed image. Disconnected records and queued tasks are pruned together, load listeners are replaced when Xiaohongshu recycles an image element, and a processing generation prevents work started before disable or restart from writing into the new lifecycle.

Xiaohongshu commonly gives the same source image different CDN transformation suffixes in the feed and expanded viewer, and it may show a bright slide background before the inner high-resolution image is ready. The bounded cache keys CDN variants by their shared source identity and also associates the feed cover with slide zero through the post ID. A passive capture-phase click listener remembers that ID before Xiaohongshu changes its SPA route, without cancelling or altering the activation. If either cache identity has already been classified, the runtime applies that result synchronously when the expanded element is discovered by the DOM observer, before waiting for decoding or another Canvas sample. Expanded-view transforms target the complete slide, keeping its background placeholder and inner image under one filter without double-processing. An image without a matching result remains unchanged until it is classified. Image brightness is exposed as an internal CSS custom property and currently defaults to full brightness.

Feed images never create control nodes. After a post opens, every viewer image receives an independent light/dark control in a closed Shadow DOM layer. Only the active slide's control is visible. It is positioned immediately left of Xiaohongshu's page count, with a matching top-right fallback for single-image posts. The setting controls whether these buttons are shown and stores their resting opacity, which defaults to 50 percent. Per-image presentation choices and classification results are memory-only.

## Document Preview

The local renderer supplements Mammoth’s content model with bounded formatting data from document defaults, inherited styles, direct properties, theme fonts/colors, numbering definitions and section page settings. Build-time hooks are checked against pinned upstream source; `scripts/document-renderer/` owns the adapter. Parsed main-document, styles and numbering XML are reused rather than parsed twice. Repeated styles share class IDs, with at most 8,192 style sets. No OCR, remote font download, layout polling or background page scanner is added.

The sandbox renders a continuous paper-like surface with source page width/margins, local font fallbacks, paragraph spacing/indentation, common numbering formats and table grids/borders/shading. Explicit page breaks and `pageBreakBefore` produce separator lines; automatic Word pagination, section-by-section paper layouts and floating objects are not emulated. Narrow windows reduce outer paper margins. The parent toolbar has a full-width divider independent of the document’s scrolling surface.

The shared font resolver keeps source names and localized aliases ahead of local substitutes, with a bounded 256-entry cache and no font discovery request, download or embedded-font execution. Word and PowerPoint runs keep Latin and East Asian font slots separate; text is grouped only when the selected font changes. More-direct explicit DOCX font settings clear inherited theme selectors for that slot; theme East Asian faces use the declared language where available. DOCX paragraph-mark sizes govern spacing metrics without replacing text-run formatting; unspecified paragraph margins use zero instead of the preview's reading defaults. Source whitespace remains literal, including blank underline runs; paragraphs and headings use `break-spaces`, so trailing spaces occupy width and blank underlines do not hang outside the line. Direct on/off properties replace inherited values, including empty XML elements that mean enabled. Numbered paragraphs use passive marker/body grid cells so long wrapped text aligns without colliding with a wide label. Source hanging indents and marker justification remain bounded style data. Numbering resolves style-linked levels, independent list instances, per-level restart rules, legal decimal overrides and Unicode dingbat bullets; DOC also keeps common Chinese numbering. Literal marker separators preserve readable copied text. Default tab intervals come from the package-local settings part, with a half-inch fallback. Irregular custom tab stops and exact Word line breaking are not emulated. An unavailable original font cannot be reproduced exactly by CSS fallbacks. Known sizes in the capture choice dialog use decimal byte/bytes/KB/MB/GB/TB/PB units, at most one fractional digit and no padded trailing zero; the preview toolbar omits size.

Common OOXML equations render as a fixed MathML subset; ruby annotations and checkbox symbols are passive text. The DOM sanitizer recreates only approved MathML elements/attributes in their namespace and drops foreign HTML, annotations and executable content. No equation library or font fetch is added. Source image extents, contextual paragraph spacing, table band sizes/corner styles, cell margins and borderless cells use the same validated style registry. Legacy DOC follows only live PICF references for embedded PNG/JPEG pictures, with bounded OfficeArt traversal and aggregate output limits; metafiles/OLE/linked pictures remain inert. Character spacing/position, default tab intervals, paragraph border/character-unit properties and safe hyperlink field results are retained. Hidden runs remain excluded.

Worker output contains HTML plus formatting data, never trusted CSS. The display boundary reconstructs an allowlisted DOM and accepts only generated class names and bounded, allowlisted property values. Raw document CSS, executable markup, external assets and XML DTD/entity declarations are rejected. EML alone may translate passive inline styles and legacy table presentation attributes into the same bounded property/value allowlist; raw styles, resource-bearing values and selectors never reach the preview. Authored classes outrank family defaults, including in dark mode. A separate dark-mode stylesheet adapts foreground, background and border colors without re-running conversion; the original file and embedded images stay unchanged.

The toolbar carries `translate="no"` and `notranslate`; it does not suppress translation of the separate document body.

Preview chrome follows browser/system appearance changes live. The opaque content frame receives a theme boolean and switches its cached validated presentation stylesheet and `color-scheme`, without relying on extension-frame media-query inheritance. Text, backgrounds, table borders, links and scrollbars adapt without re-parsing the document, rewriting images or modifying the cached original bytes. A bounded streaming inflate check verifies ZIP size claims in the render worker before conversion; Safe Browsing / content-policy blocked downloads retain Chrome's original handling.

`documentPreview.appearance` stores the default `auto`, `light` or `dark` preference, including the settings first-frame cache. Auto follows the browser. The sun/moon toggle writes a light/dark override keyed by the source eTLD+1 to `documentPreview:<context>.themes` in session storage; Default removes it and resumes the saved preference. Open previews observe session/settings changes directly, including when capture is disabled. Overrides survive worker sleep and preview reloads, are isolated between ordinary/incognito contexts, and expire with the last source website tab; preview tabs do not prolong them. Commands validate the owning document and workspace. The parent theme variables and iframe embedding `color-scheme` change together without a frame navigation, worker rerun or scroll reset.

Dark document defaults and neutral source text use `#f1f3f4`, matching the filename; source accent colors still retain their hue. Transient download/action notices clear after 15 seconds with one replaceable timer. Persistent loading, render-failure and expiration states cancel any old notice timer so they cannot be erased by a previous success notice.

Document zoom is per-preview memory, starts at 100%, and moves in 10% steps between 50% and 200%. Clicking the percentage resets it. CSS zoom on the embedding frame scales only the document while its full-width flex viewport stays fitted. No reconversion, document rescan or frame navigation is required. Controls appear only after rendering succeeds and disappear when the website session expires.

Request correlation is reattached synchronously when the service worker starts, then removed as soon as saved settings confirm the product is disabled. This preserves the first request after worker sleep without leaving a listener active while the feature is off. A closed, short-lived download tab can be resolved to a unique live tab matching Chrome's recorded referrer; ambiguous matches continue as ordinary downloads. Filename interception records only bounded request metadata and cancels the provisional Chrome task before presenting a choice. It does not fetch or cache document bytes at this stage. Dismissal removes unprepared metadata.

`documentPreview` is a default-off Customs Province product immediately above Ad Marshal in Satellites / General features. It uses Central's existing `onDeterminingFilename` entry, after Customs gives Video Download the first opportunity to name an owned media download. The listener returns the product's asynchronous-handling result so Chrome waits for `suggest()`; every branch settles that callback exactly once. No extra manifest permissions are needed.

While enabled, a bounded request ingress observes only HTTP(S) main-frame, subframe, and `other` requests, recording method, URL, and source tab for at most 60 seconds / 256 entries. It is detached while disabled. It does not observe media, image or XHR responses, install a page scanner, or read response bodies. An unambiguous observed GET, a supported provisional filename (or PDF MIME without a conflicting suffix) and a live source tab are required. POST, blob URLs, other extensions' downloads and uncertain requests retain their original Chrome task. Metadata-only filename interception has an eight-second release deadline. After an explicit Preview or Download choice, a single-flight preparation fetch uses the current browser credentials, a 30-second timeout, `cache: no-store`, bounded validation, and the existing 24-document / 64-MiB cache limits. Failures keep the choice available for retry and create no cached document. Remembered Download choices immediately retain Chrome's original task without an additional fetch.

Document records retain the source tab ID. Immediately before creating a preview or fallback choice tab, resolve its current index/window and verify the source site and browser context, then open at `index + 1` with that source as opener. Cached files requested from a different source tab use the new source. A missing or no-longer-matching source uses ordinary tab placement; do not attach previews to an unrelated tab.

The one-shot isolated-world dialog uses a closed shadow root, a top-layer dialog and a constructed stylesheet, so a page's inline-style CSP cannot break it. It shows a full wrapping filename, an optional size row, Preview / Download controls and an initially unchecked session-choice checkbox. Outside activation and Escape dismiss it. If the page cannot host it, a privileged choice tab provides the same actions. Choice commands validate the document ID, source site and sender frame; workspace commands are bound to the document's own extension URL. A contextual popup button clears a site's temporary choice.

`core/site-key.js` implements eTLD+1 against the curated `etld` snapshot, including wildcard, exception and IDN rules. IP literals and localhost remain exact host keys. Subdomains share choices and files. Only ordinary source website tabs keep a session alive; extension preview tabs do not. Tab closure and leaving the last source site tab invalidate metadata and delete the cached bytes. Disabling the feature stops new captures and aborts unfinished preparation, but preserves already prepared documents, existing previews and their download actions until the source session ends. A full extension reset clears this product's session. Browser-session metadata lives in `chrome.storage.session`; temporary original bytes live only in the offscreen document’s in-memory blob map, with context and session-epoch ownership. A neutral offscreen host serializes creation and teardown within Customs; media cleanup cannot close the host while document blobs remain. Office use does not load the media processor. Background-to-offscreen transfers use bounded 1-MiB chunks; incomplete uploads expire after one minute. Only Central’s service-worker sender may access the cache. Workspaces receive authorized blob URLs through the product and read only their own extension-origin blobs. Worker sleep preserves the offscreen map; browser exit destroys it and session storage. Startup removes orphaned records. The obsolete disk cache is deleted rather than migrated. Regular and incognito ownership is separate. Open preview tabs observe expiration and clear the rendered document, worker and file reference. An explicit download already handed to Chrome may finish.

The Document Preview whitelist is a bounded, insertion-ordered hostname list. Domains include themselves and all label-boundary subdomains; IP entries match exact addresses, independent of port. Capture checks the source page hostname (not the file CDN or eTLD+1 session key) before cancellation and again after queued work. Matching downloads keep Chrome’s normal handling; prepared previews are not invalidated. Settings uses the shared reset/clean/help interactions and first-frame cache, with a two-column domain list that collapses below 620 CSS pixels. Only Settings may mutate this list.

Each intercepted document record stores `closedAt` while no matching preview workspace remains open in its own browser context. A metadata-only prompt starts its 10-minute deadline at interception. Closing or navigating away from the last preview tab restarts that deadline; pending preview tabs count as open, and reopening before expiry clears it. Source-site termination always takes precedence, even for an open preview. One one-shot Chrome alarm per context targets the earliest deadline, is removed when none remain, and is routed Central → Customs → Document Preview. Tab lifecycle and worker initialization reconcile live tabs and persisted absolute deadlines; unrelated navigation does not extend them. Commands reject already expired documents even before a delayed alarm fires, and late reopen attempts cannot revive expired files. Cleanup continues with capture disabled, deletes metadata and any prepared bytes, and leaves site action/appearance preferences intact until the source session ends. No polling or per-document background timer is used.

The cache admits at most 24 documents / 64 MiB in total per context, with a 24 MiB per-document limit. ZIP directory preflight rejects malformed, encrypted and oversized packages; macro payloads masquerading under a non-macro suffix are also rejected before rendering. The bundled Mammoth 1.12.3 browser renderer runs only in an on-demand dedicated worker, with external file access and embedded style maps disabled and a 15-second conversion deadline. The result is rebuilt into an allowlisted DOM and rendered inside an opaque-origin sandbox whose only scripts are fixed packaged UI controllers; external images, fonts, styles and other resources are blocked. Only raster images embedded in the package and validated navigation links are retained; links pass through External Links Capture. Word pagination and complex layout are not guaranteed.

Original downloads use the current document’s cache-owned blob URL. The background product validates the workspace document ID, context and session epoch, and obtains the URL from the cache rather than trusting a workspace-supplied URL. A background download workspace closes when Chrome completes or interrupts its download. The offscreen cache owns the original blob lifetime. Chrome Downloads is called without `saveAs`, preserving Chrome's own download-location preference. Extension-generated downloads bypass preview capture, preventing loops. The preview page can also download the original bytes. The renderer and all dependency license notices are packaged locally under `vendor/mammoth`.


Format families are documents `.docx/.docm/.dotx/.dotm/.doc/.rtf/.odt`, spreadsheets `.xlsx/.xlsm/.xltx/.xltm/.xls/.ods`, presentations `.pptx/.pptm/.potx/.potm/.ppsx/.ppsm/.ppt/.odp` PDF `.pdf` and other `.eml`. `core/document-preview.js` owns MIME and family dispatch. Macro-enabled packages are accepted only for static content: no renderer executes VBA, ActiveX, OLE or embedded programs. All source parts still undergo bounded archive validation. Packages are never passed to a native Office application. Original download bytes remain unchanged and must not be described as disinfected.

`office-package.cjs` resolves package-local relationships, rejects XML DTD/entities and external targets, checks raster image signatures and bounds XML trees. Spreadsheet previews support visible sheets, shared/inline strings, cached formula results, common number/date formatting, fonts/fills/alignment, rows/columns and merged cells. They never recalculate formulas or query external workbooks/services. The workbook admits at most 100,000 populated cells; each sheet admits 20,000 rows, 256 columns and 150,000 displayed grid cells; an over-limit sheet fails instead of silently truncating data. At most 128 visible worksheets are accepted. Presentation previews use slide order and size, master/layout theme information and placeholder geometry, static text, simple shapes, tables and local raster pictures. They cap at 300 slides and 4,000 shapes per slide. Chart rendering, SmartArt, animations, audio/video and exact Office layout are outside these static readers. Worksheet/slide navigation selects a preconverted part and sanitizes it without rerunning the worker. All three Office families share the opaque, sanitized display boundary and theme/zoom controls.

Legacy formats use bounded first-party CFB, MS-DOC piece-table and MS-PPT persist-directory readers. Word 97+ text is read from the live piece table; PowerPoint follows the current UserEdit chain and live slide order, excluding orphan/deleted slide records. MS-DOC additionally resolves bounded STSH style inheritance, font tables, character/paragraph FKPs, direct and piece properties, basic list definitions/overrides, table cell grids/borders/shading/merges and first-section page metrics. Field instructions and hidden runs are not rendered; common field results remain text. Output is a continuous reading surface, not a Word pagination engine. MS-PPT resolves live master text styles, scheme colors, OfficeArt anchors/group transforms, ordinary text boxes, simple fills/borders and local JPEG/PNG blips. Unsupported drawings/media stay omitted rather than being delegated to native applications. Legacy Excel uses a separately loaded, locally bundled SheetJS CE 0.20.3 on the validated Workbook/Book stream, with macros and formula evaluation disabled. A bounded BIFF8 visual pass retains fonts, XF inheritance, palettes, alignment, solid fills, borders and row/column metrics; older BIFF retains the existing value-oriented fallback. Encrypted compound documents are rejected. RTF is parsed as bounded text/groups with local fonts/colors, paragraph spacing/indents, common table metrics/borders, Unicode/codepage handling and inert field results; objects and program payloads are omitted. OpenDocument readers share bounded ZIP/XML validation, accept package-local raster images only and reject encrypted manifests, DTD/entities and external resources. ODF style resolution separates families, caches inheritance and retains common page/list/text/table properties. Children are rendered sequentially to bound in-flight work. ODS repeated rows/columns are expanded only within grid budgets; empty trailing repetitions do not allocate large grids. EML uses pinned PostalMime 3.0.0 with bounded headers/nesting; attachment bytes are inert, names are shown as text, and only signature-checked inline raster CID images can reach the sanitized output. No mail attachment is opened or executed. Original files are never sanitized in place.

Rendering performance is bounded at conversion time: Office image reads cache one package-local promise per part; shared strings, BIFF styles and slide placeholders reuse parsed data; numeric formatters and RTF decoders have small per-worker caches. Both spreadsheet readers use a shared merge-grid pass with a cumulative 150,000-cell visit budget and reject overlaps, preserving merge-root content when rows/columns are hidden. Static HTML classes are deduplicated (maximum 8,192). Repeated image output and shape groups have byte limits before large concatenations. No new page observers, background polling, network services or eager media-library loads are added by formatting support.

All converters run in the dedicated 15-second worker with a 24-MiB input and 48-MiB final-output ceiling, plus format-specific tree, record, cell, slide and expansion bounds. HTML output is always rebuilt using the shared allowlist before reaching an opaque-origin frame that runs only fixed packaged UI code. Remote images, styles, fonts, embedded frames and document-linked data are not loaded; retained external links require confirmation through External Links Capture. Both the source dialog and preview header expose an indeterminate loading line with a localized status and no numeric percentage; reduced-motion preferences use a stationary line. Success, failure and expiry hide the line.

## Image Download

Image Download is activated for one source tab from the popup. Its workspace header identifies Cosmic Gemini first, then Image Download, followed by the product wordmark. While the popup loads, the request is routed through Customs Province and the Image Download product prepares a tab-specific `chrome.sidePanel` path before the product control becomes available. The user action therefore opens an already-configured panel instead of racing panel configuration against `chrome.sidePanel.open()`. A transient Side Panel error remains an error and never opens or focuses another tab. A normal extension tab is used only when selected in Settings or requested from the Side Panel. The same workspace document supports both surfaces, with a synchronous view preloader selecting the narrow Side Panel layout before CSS renders.

Its isolated scanner inspects ordinary and responsive images, lazy-load attributes, links to image files, computed CSS and pseudo-element images, open shadow roots, frames, inline SVG, canvas content, image metadata, JSON-LD, and existing Resource Timing entries. A browser-level response listener adds image resources that load while the session is collecting.

Candidates are normalized, deduplicated, and grouped into related families. Recommendation scoring favors explicit original links and attributes, high-resolution responsive sources, known deterministic original-image URL forms, larger verified dimensions, and useful response metadata. Alternate sizes and formats remain selectable in the same family. A normal rescan reads the current page state. Deep scan is available only after an explicit user action, briefly advances through the page to reveal lazy-loaded images, and restores the original scroll position.

The workspace keeps its complete Filters card collapsed by default. Search text, format, layout, minimum dimensions, sorting, and the clear action expand together, while a compact count reports active filters. Refreshing candidates preserves both the disclosure state and current values. The workspace can select visible results, download one image or a batch, capture a user-selected part of the visible page, preserve original formats, or convert compatible images locally to JPEG, PNG, or WebP. Multiple selections can be sent to Chrome separately or placed in a locally generated ZIP file. Workspace updates are driven by session-storage changes rather than a timer. Closing or hiding the workspace starts a two-minute discovery grace period. After that period, browser-level image collection pauses while the candidates remain available. Showing the workspace again cancels the pending pause, registers shared browser-response observation before collection resumes, and immediately scans the page. Same-origin navigation clears old candidates and starts a new scan while discovery is active. Cross-origin navigation, source-tab closure, or explicit stop removes the session and captured artifacts and disables that source tab’s Side Panel configuration.

## Video Download

Video Download is activated for one tab at a time from the popup. Its result header places the Cosmic Gemini mark and Video Download icon before a compact product wordmark. Main-world and isolated-world scanners are injected only after activation. Together they inspect media elements, page metadata, embedded frames, mutation changes, player state, fetch and XHR responses, inline streaming manifests, and buffered Resource Timing entries. A non-blocking `webRequest.onHeadersReceived` listener supplies the browser-level path and recognizes video responses and HLS or DASH manifests by URL and response MIME type. The listener itself is registered with Chrome's exact `tabId` filter only after that tab starts Image Download or Video Download. This remains effective when a page hides its player markup, moves media into a frame, embeds a manifest in script state, or repeatedly replaces its DOM.

Candidate URLs and transient download state live in `chrome.storage.session` under the tab ID. The media list renders session-storage changes instead of polling. Closing the list starts a two-minute grace period. When it expires, the page observers, fetch and XHR hooks, and browser-level response collection stop while detected candidates remain stored. Opening the list again registers shared browser-response observation before restoring the hooks, then immediately reruns page and service-specific discovery. Same-origin navigation clears stale candidates and reinjects the scanner only while discovery is active. A different origin, tab closure, or an explicit stop removes the session. Signed URLs are retained without rewriting while the session is active, but are never copied into persistent settings or history.

Customs Province coordinates the response ingress shared by Image Download and Video Download. It registers one browser-filtered listener for each exact tab with an active or grace-period collection session. If both products collect in the same tab, they share that one registration. A tab that has never activated either download product has no download response listener, and the registration is removed when the last collection session in that tab pauses or ends. Service Worker startup restores known product sessions before registering their exact tabs; an uncertain restoration never enables an all-tab fallback. Concurrent restoration requests share one task.

Before a selected source is fetched, the Video Download product installs temporary session rules for its media directories so restricted request headers such as the active-page `Referer` reach authenticated and referrer-sensitive servers. The rules apply only while the selected media is being prepared and are removed afterward. Direct files are streamed through the Customs Province offscreen coordinator. Compatible HLS playlists are parsed locally, including master variants, alternate audio, initialization maps, byte ranges, standard AES-128 keys, live snapshots, and supported wrapped playlist formats. DASH supports BaseURL, SegmentList, SegmentTemplate, SegmentTimeline, byte ranges, separate audio and video representations, and common protection markers.

Separated HLS, DASH, Bilibili, and YouTube tracks are remuxed locally with the bundled Mediabunny build. MP4-compatible tracks produce MP4 output; WebM-family combinations use MKV. Remote separated tracks are streamed to temporary OPFS files and validated before remuxing, so a CDN does not need to support random-access Range responses and the complete sources do not occupy memory. The popup shows page metadata for source confirmation and groups equivalent codec or internal-track candidates into one preferred choice per main quality. Technical details remain in the selected-result summary, and compatible standalone Bilibili or YouTube audio tracks appear as Audio only. Event-driven renders preserve a focused quality control while download progress changes. This path does not start the player and therefore remains available while No Autoplay is active. Primary and alternate Bilibili CDN addresses remain attached to each video and audio track so local preparation can retry an unavailable route. Dedicated page adapters cover the service-specific sources represented by Vimeo, Facebook and Instagram inline DASH, OK, VK Video, Canva, iQIYI, TwitCasting, Osmosis, Kick, Chaturbate, and wrapped xgplayer HLS.

Each preparation carries one request ID through the popup, routing hierarchy, network readers, playlist assembly, and remuxing pipeline. The red cancel control aborts the active readers, stops local packet processing, removes partial OPFS artifacts, rejects stale progress from that request, and returns the candidate to its ready state before Chrome Downloads receives a file. Completed artifacts are removed after Chrome completes or interrupts the download. DRM decryption is not implemented.

## State and lifecycle

Settings pages receive two separate views of state. A normalized, read-only preference snapshot is the sole source for persistent switches, rules, and selectors. Product state separately describes current-page support, matching, activity, availability, schedules, scans, and browser-rule reconciliation. Derived state can inform status presentation but cannot redefine a saved preference.

For ordinary windows, `chrome.storage.local` stores one versioned settings object:

- NSNA: one shared whitelist that deactivates both Native Scroll and No Autoplay
- Native Scroll: a global enabled default plus Always inactive, Always Standard, and Always Enhanced website rules
- No Autoplay: a global enabled default plus Always inactive, Always Standard, and Always Enhanced website rules, an all-sites audio autoplay setting, and hostname-specific audio autoplay rules
- Any Copy: its own site rules
- Any Copy Enhanced: current-tab activation for the browser session
- Mailto Capture: one enabled setting
- Page Display: one master authorization, independent Reduce White Point and Greyscale states, plus reduction strength
- XHS Image Dark Mode: enabled state, page-wide dark-mode override, image-control visibility, and control opacity
- Image Download: workspace location, default output format, batch-download behavior, and save-location preference
- Video Download: preferred quality and whether Chrome should ask for a save location
- Satellites: Bili Daily Login switch state, last completed date, and most recent attempted schedule slot
- Ad Marshal: two independent managed-site selections; the Tencent News selection coordinates two separate internal policies
- Interface locale

Initial ordinary-window settings also leave every automatic product inactive, including Native Scroll, No Autoplay, Mailto Capture, and Website Knowledge Control's independent categories. Normalization preserves explicit saved `enabled: true` choices; only missing values use the new off defaults. Download prompts and other preferences that do not activate a product retain their own defaults.

The split incognito background ignores that persistent object. It keeps a separate `chrome.storage.session` object with Native Scroll, No Autoplay, and every other automatic product inactive by default. Explicit incognito choices remain in that temporary object only while the current set of incognito windows exists.

A window-identity marker removes stale settings when a new incognito session begins and deletes the temporary object when the final incognito window closes. Incognito locale changes follow the same boundary, Reset All Settings in incognito does not change ordinary settings, and Bili Daily Login is unavailable in the incognito process.

Every user-maintained website-rule list preserves insertion order without storing timestamps. Adding an existing entry keeps its original position; deleting and later adding the same entry places it at the end. The Settings rule editors reserve two case-insensitive input commands. Submitting `reset`, or pressing and holding Add for 550 ms while its input is empty, alphabetizes the list or lists managed by that editor; later additions continue at the end. Submitting `clean` opens a localized confirmation prompt and clears every website-rule entry managed by that card only after confirmation. Entering `?` or `？` opens a localized contextual panel describing the current field's accepted rule forms and shortcuts, then clears the help token without storing it. For a Native Scroll or No Autoplay website-behavior card, either command applies together to its inactive, Standard, and Enhanced lists. The shared NSNA whitelist, No Autoplay audio allow list, Any Copy site list, and Access Control blocked-site list are handled independently by their own editors. These commands are routed through the same Central → province → product settings path as ordinary list changes and are never stored as website-rule entries.

Exact rules accept domain hostnames, canonical IPv4 addresses, and canonical IPv6 addresses. IPv6 entries are stored in bracketed URL-host form. Wildcards remain limited to domain names. In Settings rule inputs, a leading-dot multi-label domain is expanded to a wildcard, and a directly entered multi-label rule from the shared `etld` reference is also expanded to a wildcard. Single-label TLDs are excluded from both input conveniences and remain invalid website rules. Paths, ports, queries, complete URLs, malformed addresses, and ambiguous IPv4 forms with leading zeros are rejected. A saved exact rule matches its host on every port because URL matching reads `hostname` separately from `port`. Matching prefers an exact rule, then the most specific wildcard. Access Control additionally resolves `xhs` or `xiaohongshu` to `xiaohongshu.com`; `dy` or `douyin` to `douyin.com`; `bili`, `bilibili`, or `bzhan` to `bilibili.com`; and `ins`, `ig`, or `instagram` to `instagram.com`. It uses exact IP network rules and does not append its domain-only subdomain label to IP entries. The shared NSNA whitelist has highest priority and deactivates both products without deleting their product-specific rules. Each Native Scroll or No Autoplay rule belongs to exactly one behavior: inactive, Standard, or Enhanced. Standard and Enhanced rules activate matching websites even when the global default is off. Saving or changing a rule removes that exact rule from the other behavior lists, while a more-specific rule can intentionally override a broader one.

Access Control implements saved blocks as session DNR navigation rules. Its independent one-time-visit checkbox defaults off and is stored inside the Access Control preference without changing the master authorization. When enabled, a main-frame network failure on a saved blocked domain temporarily records that tab's destination in session storage, because Chrome's blocked-navigation error tab may expose neither `url` nor `pendingUrl`. Only that tab gets an empty action popup, so clicking the toolbar action reaches Central and Standing Province without opening the control popup. The product installs a higher-priority `allow` rule limited to that tab and matched domain, then retries the captured destination with `tabs.update`. The normal popup is restored after allowance, navigation away, or disabling the option. The saved block list is unchanged. The shared `etld` reference is generated from the current official Public Suffix List. It contains the complete ICANN section, preserving ordinary, wildcard, exception, and Unicode rules. The generated vendor file records the PSL version, commit, SHA-256 digest, and counts; `scripts/update-etld.mjs` refreshes the snapshot without adding a runtime network request.

Settings' general domain inputs—Access Control, Document Preview's whitelist, and Website Fixer's whitelist—accept a pasted HTTP(S) URL and reduce it to the curated eTLD+1 before applying the existing root-and-subdomain rule. Bare domain entries keep their former meaning, including a specific subdomain when entered directly. Access Control aliases and exact IP entries remain supported; Website Fixer still rejects IP entries. Other website-rule editors do not reinterpret URLs. Empty form-message nodes use `display: none` so scoped paragraph styles cannot reserve vertical space; list empty-state rows also avoid the populated-row minimum height. `.rule-panel` description sizing applies only to an introductory paragraph. A localized scope note appears below lists containing at least one domain, but not IP-only lists. Individual entries display only their saved value.

The popup uses five fixed paired rows: Native Scroll with its Enhanced control, No Autoplay with its Enhanced control, Any Copy with Any Copy Enhanced, the global Reduce White Point and Greyscale settings, and Image Download with Video Download. ## Resource use

The runtimes are event-driven. There is no analytics code or persistent background page. Observers are feature-scoped and activated only when required: after Any Copy detects a restriction, while Any Copy Enhanced displays a reading view, while No Autoplay Enhanced mode removes newly inserted media, during an explicitly activated download session, or on the exact `news.qq.com` host while its Ad Marshal policy is enabled. Mailto Capture uses delegated activation listeners without a DOM observer or polling, and it creates its Shadow DOM only after a supported email, telephone, or text-message link is selected. Page Display is absent while its master is off or both subfeatures are disabled. While Reduce White Point is active, one scoped observer follows appearance changes on the page root, body, and theme styles so the composited overlay remains darkening under page-wide filter changes; it never scans content or runs periodic work. XHS Image Dark Mode performs no image scan while disabled or waiting for page-wide dark mode. When processing is active, mutation and intersection events drive a two-task analysis queue; resize observation is limited to expanded-view controls. Unloaded lazy images wait outside the queue until their load event, completed ordinary photographs leave observation immediately, and newly visible images can upgrade an existing queued task. Each aspect-ratio-preserving sample contains no more than 1,024 pixels, and a bounded 240-entry in-memory cache avoids repeat classification. If Xiaohongshu loaded a displayed image without CORS mode, the runtime obtains a CORS-enabled copy from that same image URL, normally through the browser cache, so Canvas can read the reduced sample without altering the displayed element. Classification remains local and no image is sent to an analysis service. Image Download and Video Download views react to session-storage changes instead of polling. Image or media fetching, processing, and the offscreen document start only after a download or capture action. Ad Marshal's native network rules are limited to active managed-site tabs. Its `news.qq.com` observers react only to added nodes and selected media or player attributes, and all other Ad Marshal policies run without observers. No Ad Marshal policy uses a timer or polling loop. Bili Daily Login contacts Bilibili only from its own alarm while Chrome and the computer are running.

## Browser boundaries

Chrome does not allow content scripts on internal pages such as `chrome://`, the Chrome Web Store, or some built-in viewers. Cosmic Gemini remains inactive there. Image Download can retrieve only image sources available to the current browser session. Video Download does not decrypt DRM systems or circumvent access controls. A source may stop working when its public page or playback API changes, in which case its local adapter must be updated.

## Google search result language commands

`lang-google` (`langGoogle`) is a default-off Standing Province product at the end of Satellites, in Site-specific features. Ordinary and incognito settings remain separate. The saved authorization is included in Settings hydration, its first-frame cache, and the platform's page-settings signature.

The product accepts HTTP(S) `/search` and `/webhp` URLs on exact Google search hosts, from a bundled copy of Google's supported-domains list. It requires exactly one `q` parameter. Case-insensitive, whitespace-delimited `lang:` commands accept comma-separated language tags. Multiple valid commands combine languages with Google's `|` OR syntax and replace any previous `lr`. Unsupported commands (including partially unsupported comma lists), negated tokens, and double-quoted phrases remain search text. The rewrite removes consumed commands, resets `start`, and preserves all other parameters, including search modes (`tbm`, `udm`), interface language (`hl`), and region (`gl`). It does not alter Google interface language or guarantee how Google ranks or filters each result type.

`zh` and `zhs` select `lang_zh-CN`; `zht` selects `lang_zh-TW`. For Chinese BCP 47 tags, an explicit Hans/Hant script takes precedence, otherwise Intl likely-subtags resolve the script from the region. Other supported language tags resolve to the Google result-language collection for their base language. Underscores are accepted as tag separators. The bundled result-language set comes from Google's advanced-search form, not the larger interface-language set.

Central's existing document-start synchronization and tab URL-update events dispatch the product. Disabled, non-search, ordinary no-command searches, and child frames never receive a product injection. Only eligible commands cause a one-shot isolated-world `location.replace`, guarded by the exact source URL and document identity where available. Concurrent work is coalesced and released after completion; a document-local guard prevents duplicate replacements while navigation is pending. There are no persistent query records, network calls, DOM scans, mutation observers, or polling. Disabling the feature stops future conversions; it does not undo an already submitted search filter.

Sources: [Google supported domains](https://www.google.com/supported_domains), [Google Advanced Search](https://www.google.com/advanced_search?hl=en), and [Google language-filter and Boolean-operator reference](https://developers.google.com/custom-search/docs/xml_results_appendices).

## Customs processing boundary

The offscreen dispatcher and media handler accept only the extension’s exact Central service-worker sender. Content scripts and extension workspaces cannot directly invoke media processing, inspect the document blob cache or request artifact deletion. Document chunks include an exact byte offset, canonical base64 and per-chunk limits; empty, replayed, malformed or out-of-order chunks abort the upload. Cached originals are bound to their document, session epoch and regular/incognito context.

Buffered media reads enforce actual streamed sizes, not just Content-Length: 8 MiB per HLS/DASH manifest, 128 MiB per buffered segment and 64 MiB per image. Conversion canvases are limited to 64 megapixels. Original streamed media downloads are not subjected to a total-video size ceiling. AES-128 requires a 16-byte key, screenshot cropping accepts only bounded PNG/JPEG data URLs, ZIP member names cannot contain path separators, and fallback artifact deletion accepts only generated artifact names. These are defense-in-depth limits, not malware certification. PDF Viewer uses its own isolated, read-only local renderer and restrictive content policy as described above.

### Single Settings surface

Administration receives trusted Settings document registrations through Central and Operations Province. All Settings and allowlisted feature pages form one surface per normal/incognito context. A session-only registry of live document IDs/start times (no URLs/content) orders delayed/concurrent loads and survives background restarts. `runtime.getContexts()` inspects only extension documents without broad tabs permission; cleanup rechecks both old and retained document identities before closing a tab. Unregistered loading documents await their own registration instead of being guessed to be old. BFCache returns register a new visit time. Other extension surfaces and privacy contexts remain separate; no polling or new permissions are needed.

The injected Document Preview choice prompt reserves a compact progress line inside its button row, left of Preview. Loading changes visibility/accessibility state only; it adds no status line or layout height. Idle animations are paused, reduced motion is respected and error feedback remains distinct.

PDF Viewer suppresses page-interior loading pseudo-elements. Its existing toolbar-divider line combines initial/print work with visible-page rendering that lasts over 200 ms. The renderer’s existing visible set is reused; no extra DOM walk, geometry scan, polling or render allocation is introduced. Completion, hidden tabs and disposal clear render feedback; background prefetch and cached pages stay quiet.

The opaque reader uses `worker.js` to adapt the pinned, self-contained PDF.js worker module into a classic blob worker: remove its checked export footer and resolve `import.meta.url` to the fixed packaged asset. This avoids Chrome’s opaque-origin module-worker redirect failure. The adapter waits for the native ready message, passes its port to PDFWorker, and explicitly owns termination/blob disposal on failure, abort and normal teardown; it never falls back to a main-thread fake worker. Startup has a bounded deadline. Dependency upgrades must revalidate the adapter and real-worker browser assertion.

The fixed reader iframe delegates only the `clipboard-write` Permissions Policy feature (opaque origin requires `*`); clipboard read remains disabled and no clipboard permission is added to the extension manifest. PDF.js whole-document Copy and link-copy fallbacks stay local, without sending document text through the privileged bridge. Dialog opening temporarily makes the dialog inert during native initial-focus selection, restores it synchronously and explicitly focuses the heading/input/button without scrolling. Native modal isolation, Escape and return focus remain intact; no cross-origin `autofocus` attributes are used.
